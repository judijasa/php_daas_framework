# Keep nix & Composer ema pin in sync — Plan & Progress

## Decision

php_daas_framework fetches ema two ways — as a nix flake input
(`flake.nix` → `flake.lock`) and, once it `require`s ema, as a Composer
package (`composer.json` → `composer.lock`). Each pins an upstream commit
independently, so the two can drift.

Add a pre-commit gate that asserts both resolvers agree on the ema commit
whenever `flake.lock` or `composer.lock` is staged, and blocks on mismatch.
As with consumers' own lock-sync gates, the assertion is authoritative:
regenerating the other lock alone does not guarantee agreement, because a
`dev-main` Composer constraint resolves to current `main` HEAD, independent of
the flake rev.

## Mechanism

| package | `flake.lock` rev | `composer.lock` ref |
|---|---|---|
| ema | `nodes.ema.locked.rev` | `packages[]` `name == judijasa/ema` → `source.reference` |

The row is dormant until php_daas_framework `require`s ema (before that, ema
is absent from `composer.lock` and the hook skips it).

## Changes

### php_daas_framework (php_daas_framework)

- [ ] `hooks/pre-commit-lock-sync.sh` (new): when `flake.lock` or
      `composer.lock` is staged, compare `nodes.ema.locked.rev` against
      `judijasa/ema`'s `source.reference` (via `jq`) and fail on mismatch.
      Skips when ema is absent from `composer.lock`.
- [ ] `.pre-commit-config.yaml`: register the `lock-sync` local pre-commit id
      (mirrors the existing `composer` id).
- [ ] Land the hook only after `composer.json` gains the ema `require` (part
      of the consumer-side wiring of the ema distribution plan) — otherwise it
      is a no-op.
